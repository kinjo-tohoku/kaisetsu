# 検証記録: Le Bail の分配更新でデータ範囲外の反射が暴走する不具合

- 日付: 2026-10-16(kaisetsu 0.1.9 → 0.1.10 開発版)
- きっかけ: ユーザー「Le Bail で強度合わないのなんでだよ」
- スクリプト: `scratchpad/lebail_repro.py`(PbSO4 の再現)、`lebail_debug.py`(反射ごとの追跡)、
  `avm_lebail_redo.py`(COD 比較の Le Bail 下限の出し直し)(セッション一時領域)
- テスト: `tests/unit/test_lebail_outside_range.py`

## 1. 現象(PbSO4 CuKα、`data/public/pbso4/PBSO4.XRA`、10–160°、6001 点)

構造から作った強度で Le Bail を始め、分配更新(`Project.le_bail_update`)だけを繰り返したときの Rwp。

| 更新回数 | 修正前 | 修正後 |
|---|---|---|
| 0(構造の強度、スケール 1 固定) | 488% | 50.5%(開始時に更新を回すようにした) |
| 1 | 51.3% | 50.5% |
| 2 | 1035% | 50.5% |
| 3 | 1997% | 50.5% |
| 5 | 2340% | 50.5% |
| 15 | 2705% | 50.5% |

修正前の 2 回目以降で膨らんでいたのは 2θ = 161.2°, 161.7°, 161.9° の 3 本(546, 905, 463)。
データは 160° で終わるが、反射は x_max + 2° のマージン(`HistogramEntry.d_min_margin_deg`)まで
計算するので、この 3 本は裾だけがデータの端に掛かる。分配は「反射自身の寄与が最大値の 1% 以上の点」で
観測/計算の正味強度の比を取るので、裾しか無い反射では「データ端の点の観測/計算比」になる。端では
背景の残りで観測が計算を数百倍上回っていたため、1 回目で 600 倍、2 回目で 2500 倍に膨らんだ
(ic 11 → 7.1e3 → 1.8e7 → 3.5e7)。さらに表の下限(最大値の 1e-4)がこの値に引きずられて、
弱い反射が全部底上げされ、パターン全体が崩れた(Σ 計算 2.2e7 対 Σ 観測 1.4e6)。

精密化の経路ごとの Rwp(修正前 → 修正後):

| 経路 | 修正前 | 修正後 |
|---|---|---|
| GUI「精密化」1 回(`refine()`、背景・格子定数・ゼロ点・U V W X Y) | 89.1% | 8.56% |
| 同 2 回目 / 3 回目 / 5 回目 | 48.9 / 43.2 / 39.9% | 8.20 / 8.14 / 8.12% |
| `refine(le_bail_cycles=3)` 1 回 / 3 回 | 43.2 / 36.3% | — |
| `le_bail_recipe`(背景 → 格子定数 → 幅 W → U V X Y → 最終) | 3.3e14 % | 8.24%(31 s) |

修正前は「精密化」を 5 回押しても 40% で、ピークの強度が観測の半分や数倍のまま止まって見える。
これが「Le Bail で強度が合わない」の正体。範囲外の反射があるデータ(高角まで測った実験室データ
ほぼ全部)で起きる。放射光の合成 CeO2(4–36°)のテストでは端に反射が無く、気付かなかった。

## 2. 修正

- `refine.rfactors.reflections_inside`: 反射の中心がデータ範囲とフィット範囲のマスク(x_min, x_max、
  除外領域、重み 0)の中にあるか。
- `partition_intensities` / `partition_uncertainties` に `mask`(フィット範囲の点だけ使う)と
  `inside`(外の反射は計算値を返す)。反射レポート(R_Bragg)と MEM の F_obs も同じ扱い
  (外の反射は σ = I_calc)。
- `Project.le_bail_update(max_iter, tol)`: 外の反射は更新せず範囲内の反射の |F|² の中央値にする。
  max_iter > 1 なら Σ|ΔF²|/ΣF² < 1e-3 まで繰り返す(PbSO4 で 1 回 24 ms)。
- `Project.refine`: Le Bail 相があれば最小二乗の前に更新を収束まで回し(構造の強度のまま最小二乗を
  始めると幅と背景が引きずられる)、`le_bail_cycles=0`(GUI の「精密化」ボタン、API の既定)なら
  Rwp の改善が 1e-4 未満になるまで最大 5 回繰り返す。終了時に更新後の強度でパターンを計算し直す
  (以前は完了メッセージの Rwp が更新前の強度のものだった: 押下 1 回目で 191.7% と 89.1%)。
- `Project.start_le_bail(update=True)`: 初期値を作ったら分配で観測に合わせる。

### 2a. 分配の重み: Rietveld の分配(面積合わせ)だけでは背景と強度が互いに逃げる

範囲外の修正だけで COD 比較(3 節)の Le Bail 下限を出し直すと、放射光の La/Y ケイ酸塩
(1508527〜1508532、λ = 0.413 Å、FWHM 0.01〜0.02°、2–17° の 15,000 点)だけが Rietveld より
悪いまま残った(1508532: Rietveld 4.45% に対し Le Bail 12.55%)。Rietveld 解から分配更新した
だけで 6.61% に悪くなり、「更新 → 最小二乗」を繰り返すと背景だけ動かしても 6.6 → 19.6%、全部
動かしても 6.6 → 12.6% と単調に悪くなる(`avm_lebail_drift.py`)。

| 周期 | Rwp(背景だけ) | 背景平均 | ΣI |
|---|---|---|---|
| 開始 | 6.61% | 69.0 | 3488 |
| 1 | 8.13% | 78.8 | 3445 |
| 3 | 13.00% | 108.1 | 3384 |
| 5 | 19.55% | 144.2 | 3343 |

Rietveld の分配は反射の中心部(寄与が最大の 1% 以上、±5 FWHM)の面積を観測に合わせる。
擬 Voigt の裾が観測と合わないデータでは、面積を合わせるとピークの山が観測より低くなり、
最小二乗(重み 1/y)はそれを背景を上げて埋め、背景が上がると正味の観測が減って次の分配で
強度がさらに下がる、の循環になる。分配に使う範囲を広げる(core_fraction 1e-3、0)と背景の
誤差まで強度に入ってさらに悪い(5 周で 56.7%、71.5%)。

対策: 点ごとの観測/計算比を c_k ではなく最小二乗と同じ重み w c_k²(w = 1/σ²)で平均する
(`partition_intensities(weights=...)`)。孤立した反射では重み付き最小二乗のスケール
Σ w c y / Σ w c² と同じになり、完全に重なった反射はモデルの比のまま(分配の性質は保つ)。
1508532 で開始 3.98%、5 周で 3.92%(Rietveld の 4.45% より良い)。

ただし表を作った直後(幅が大きく外れている)は面積合わせの方が初期値として正しい。PbSO4
20–60° の切り出しで W = 0.003 だけの初期値から全部(背景・格子定数・ゼロ点・U V W X Y)を
動かすと、重み付きだけでは負の X, Y(低角でローレンツ幅 0)の極小に落ちて Rwp 19.3%
(幅の罰則を付ければ 8.7%)、面積合わせは 8.9%。そこで `start_le_bail`、レシピの最初の更新、
`refine` の最初の周期は面積合わせ(weighted=False)、以後の周期と最後の更新は重み付きにした。
この組み合わせで PbSO4 全範囲「精密化」1 回 8.41%(5 回で 8.03%)、標準手順 8.18%、切り出し
8.7%、1508532 は 3.9%。
